# claude-proxy

[readme in english](README.md)

У вас есть платная подписка Claude, но сторонние инструменты требуют отдельный API-ключ. Этот сервис работает как локальный релей: он принимает стандартные вызовы Anthropic API и отправляет их через OAuth вашей подписки. В итоге hermes, openclaw, curl и другие клиенты расходуют лимиты подписки, а не платный баланс API.

## Возможности

- Читает OAuth-токен Claude с диска при каждом запросе - поддерживается ротация токенов без перезапуска.
- Проксирует запросы на `api.anthropic.com` со всеми заголовками, необходимыми для работы через подписку.
- Корректно парсит и модифицирует JSON и SSE как структуры данных, а не через конкатенацию строк.
- Автоматически повторяет запросы при ошибках 429 и 5xx с экспоненциальной задержкой (backoff).
- Переименовывает вызовы инструментов, не поддерживаемых в рамках подписки (MCP, memory tools).
- Ноль npm-зависимостей: написан исключительно на стандартной библиотеке Node.js.

## Чем проект не является

- Не является официальным продуктом Anthropic и не аффилирован с компанией.
- Не является публичным сервисом: запускается локально на вашей машине и использует только ваши учетные данные.
- Не содержит чужих ключей или токенов: в репозитории нет приватных данных.

## Отказ от ответственности

Прокси пускает трафик через OAuth-токен подписки в обход официального клиента. Это находится в серой зоне условий использования (ToS) Anthropic. При агрессивной нагрузке есть риск блокировки аккаунта. Используйте на свой страх и риск.

## Системные требования

- Node.js 24+
- `~/.claude/.credentials.json` - создается автоматически после авторизации в Claude Code. Без этого файла прокси работать не будет.

## Запуск

```bash
git clone https://github.com/vlelyavin/claude-proxy.git
cd claude-proxy
node src/cli.js
```

Команда `npm install` не требуется. По умолчанию сервис слушает порт `127.0.0.1:18801`.

```bash
curl -sS http://127.0.0.1:18801/health
```

Эндпоинт `/health` возвращает тип подписки и срок действия токена. Статус `token_expired` означает, что прокси работает штатно, но сессия подписки истекла.

Идентификаторы моделей нужно указывать полностью (`claude-opus-5-5`). Короткие имена вроде `opus` вернут 404.

Anthropic ограничивает доступ к новым моделям в зависимости от версии Claude Code, переданной в заголовках биллинга. Если модель возвращает ошибку `claude_code_version_too_old`, обновите значение `cc_version` в преамбуле (в дефолтной конфигурации или в `config.json`) до версии, указанной в сообщении об ошибке, и перезапустите прокси. Имена моделей указываются через дефис (`claude-opus-5-5`), а не через точку.

## Конфигурация

Файл конфигурации опционален: базовые настройки подходят для большинства сценариев.

```bash
cp config.example.json config.json
node src/cli.js --config ./config.json
```

Параметры позволяют настроить хост, порт, таймауты, политики повторов, пути к файлам авторизации, правила трансформации запросов и лимит размера тела.

## Настройка hermes

Важно: hermes не определяет протокол автоматически для локальных loopback-адресов. Без флага `api_mode: anthropic_messages` запросы будут отправляться в формате `chat_completions` и завершаться с ошибкой 404.

```yaml
# ~/.hermes/config.yaml
custom_providers:
  - name: anthropic_proxy
    api_key: none
    api_mode: anthropic_messages
    base_url: http://127.0.0.1:18801
    discover_models: false
    model: claude-opus-5-5

model_aliases:
  opus:
    model: claude-opus-5-5
    provider: custom:anthropic_proxy
    api_mode: anthropic_messages
```

## Настройка openclaw

```bash
openclaw config set models.providers.anthropic.baseUrl '"http://127.0.0.1:18801"' --strict-json
```

## Проверка работы

```bash
curl -sS http://127.0.0.1:18801/v1/messages \
  -H 'content-type: application/json' \
  -H 'anthropic-version: 2023-06-01' \
  --data '{"model":"claude-opus-5-5","max_tokens":32,"messages":[{"role":"user","content":"reply with exactly: pong"}]}'
```

Ответ `pong` означает, что весь пайплайн настроен и работает корректно.

## Запуск через systemd

```bash
sudo ./scripts/install-systemd.sh
```

Скрипт создаст юнит, включит автозапуск и сразу запустит сервис. Инструкции по ручной установке находятся в файле `docs/systemd.md`.

## Структура проекта

```
src/
  config/         дефолты, валидация, загрузка
  credentials/    поиск кред claude
  rewrite/        трансформы json + sse в обе стороны
  upstream/       ретрай-aware клиент
  server/         http-поверхность + /health
scripts/          systemd-инсталлер
test/             36 тестов, сеть не нужна
```

## Безопасность

- Биндите сервис только на localhost, если нет явной необходимости открывать доступ наружу.
- Никогда не коммитьте `config.json` и файлы с учетными данными.
- В случае компрометации токенов немедленно перевыпустите их.
